# 记录格式

库根目录下的 `knowledge/index.md` 只记录类型、稳定 ID、常用别名和相对文件链接。ID 用小写短横线，别名可以中文。项目改名通常补别名，不更换 ID。

记录使用普通 Markdown，不依赖数据库或额外解析器。按事实组注明来源和确认日期；同组事实共用来源即可。采用 `YYYY-MM-DD`，用户时区已知时使用用户时区。只更新实际重新确认过的事实组日期。

按需要使用以下位置，无内容不建空文件：

| 位置 | 归属内容 |
| --- | --- |
| `knowledge/projects/<id>.md` | 项目身份、用户确认的别名、仓库标识、维护文档与相关服务入口 |
| `knowledge/environments/<id>.md` | 该机器/环境的代码目录、配置位置、运行方式和项目映射 |
| `knowledge/services/<id>.md` | 共用服务的用途、依赖项目、按环境区分的地址与配置引用 |
| `knowledge/runbooks/<id>.md` | 有明确适用范围和前置条件、已经验证的可复用流程 |

项目内的权威文档优先记录仓库相对路径，通过环境映射定位；库内链接使用相对路径。仓库 URL 如需保存，先去掉凭据、查询参数和片段。来源可写“用户于某日明确说明”或“某路径的某节，经只读检查”，无需保存整段对话。

最小条目形状（标题按内容调整，无需补空字段）：

```markdown
# 条目名称

ID：稳定标识
范围：项目、机器或运行环境的明确范围

## 已知信息

- 精简事实，或包含事实的表格。

来源：用户于 YYYY-MM-DD 明确说明；尚未执行启动验证。
确认日期：YYYY-MM-DD

## 维护入口

- 权威文档位置与用途。

来源：实际读取的文件及章节。
确认日期：YYYY-MM-DD
```

对于启动、测试、迁移等命令，记录工作目录、配置入口及已知外部副作用。只在实际执行成功后标注“验证成功”；来源文档列出的命令标为“文档入口，未执行验证”。需要调用模型、写数据库或访问外部服务的前置条件仍由具体任务授权决定。

新值与已确认旧值冲突时，用户明确纠正可直接更新。只有观察现象、不确定是临时覆盖还是长期变更时，不把它升格为永久配置；在当前任务核实，确有必要再澄清。
